# План Реализации Приложения "Домашняя Бухгалтерия"

## Описание Цели
Создать современное, адаптивное (SPA) веб-приложение для ведения домашней бухгалтерии. Приложение должно заменить текущую Excel-таблицу, предоставляя функционал для учета доходов, расходов, накоплений и управления месячными лимитами. Также требуется аналитика для визуализации трат и контроля бюджета.

## Требуется Проверка Пользователем
> [!IMPORTANT]
> **Предположения о Модели Данных**: Основываясь на вашем описании, я предполагаю следующую логику (пожалуйста, подтвердите):
> - **Категории**: Общий список категорий. Можно добавлять новые в любой момент. Можно "скрывать" их (флаг активности).
> - **Месячные Лимиты**: Лимиты устанавливаются для каждой категории индивидуально на каждый месяц.
> - **Накопления (Копилки)**: Отдельные сущности с балансом. Учитываются пополнения и снятия.
> - **Хранение**: Локальная база данных SQLite, хранящаяся вместе с сервером.

## Предлагаемый Стек Технологий
- **Frontend**: React (Vite) + TypeScript
- **Стилизация**: Tailwind CSS (для быстрого и красивого UI)
- **Графики/Аналитика**: Recharts (или Chart.js)
- **Навигация**: React Router
- **Backend**: Node.js + Express
- **База Данных**: SQLite (библиотека `better-sqlite3`)
- **API**: REST JSON API

## Структура Проекта
```text
/
  client/         # Frontend (React + Vite)
  server/         # Backend (Express + SQLite)
  package.json    # Корневые скрипты для запуска
```

## Схема Базы Данных (SQLite)

### `categories` (Категории)
- `id` (INTEGER PRIMARY KEY)
- `name` (TEXT) - Название
- `is_active` (BOOLEAN DEFAULT 1) - Для возможности скрыть категорию

### `months` (Месяцы)
- `id` (INTEGER PRIMARY KEY)
- `year` (INTEGER)
- `month` (INTEGER) (1-12)
- UNIQUE(year, month) - Уникальность сочетания год-месяц

### `incomes` (Доходы)
- `id` (INTEGER PRIMARY KEY)
- `month_id` (INTEGER FOREIGN KEY) - Привязка к месяцу
- `source` (TEXT) - Источник дохода
- `amount` (REAL) - Сумма
- `date` (TEXT ISO8601) - Дата

### `expenses` (Расходы)
- `id` (INTEGER PRIMARY KEY)
- `month_id` (INTEGER FOREIGN KEY)
- `category_id` (INTEGER FOREIGN KEY)
- `amount` (REAL) - Сумма
- `date` (TEXT ISO8601)
- `comment` (TEXT) - Комментарий (опционально)

### `budgets` (Лимиты по категориям на месяц)
- `id` (INTEGER PRIMARY KEY)
- `month_id` (INTEGER FOREIGN KEY)
- `category_id` (INTEGER FOREIGN KEY)
- `limit_amount` (REAL) - Установленный лимит

### `savings_goals` (Копилки)
- `id` (INTEGER PRIMARY KEY)
- `name` (TEXT) - Название цели
- `target_amount` (REAL) - Целевая сумма (опционально)
- `current_amount` (REAL) - Текущий баланс

### `savings_transactions` (Операции по копилкам)
- `id` (INTEGER PRIMARY KEY)
- `goal_id` (INTEGER FOREIGN KEY)
- `amount` (REAL) - Сумма (+ депозит, - снятие)
- `date` (TEXT ISO8601)
- `month_id` (INTEGER FOREIGN KEY) - Чтобы учитывать расходы на накопления в бюджете месяца

## Дизайн и UX
- **Дашборд**: Сводка за текущий месяц (Доходы vs Расходы vs Лимиты).
- **Месячный вид**: Таблица доходов и расходов. Возможность переключения месяцев.
- **Бюджетирование**: Интерфейс для настройки лимитов категорий на месяц.
- **Аналитика**: Графики (пироги, столбики) по категориям и тренды по месяцам.
- **Копилки**: Карточки копилок с прогресс-барами.

## Этапы Разработки

### Этап 1: Настройка и Бэкенд
1. Инициализация структуры проекта (client/server).
2. Настройка сервера Express.
3. Создание БД SQLite и схемы таблиц.
4. Создание базового API (CRUD для категорий, транзакций, бюджетов).

### Этап 2: Основа Фронтенда
1. Инициализация Vite + React + TS + Tailwind.
2. Создание макета (Layout) и навигации.
3. Настройка API клиента.

### Этап 3: Основной Функционал
1. **Категории**: Управление списком.
2. **Ввод Данных**: Формы для добавления доходов и расходов.
3. **Бюджет/Лимиты**: Установка лимитов для категорий.
4. **Копилки**: Управление накоплениями.

### Этап 4: Аналитика и Полировка
1. Сводные панели с расчетами (остаток лимита, перерасход).
2. Графики аналитики.
3. Адаптивность под мобильные устройства.
