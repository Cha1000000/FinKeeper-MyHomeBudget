# Руководство по приложению "Домашняя Бухгалтерия"

Это актуальное руководство по запуску и использованию FinKeeper с учётом текущей реализации:

- web-клиента
- серверной части
- Kotlin Multiplatform приложения

## Что представляет собой система

FinKeeper — это мультиплатформенное приложение для ведения личных финансов.

Поддерживаются:

- доходы
- расходы
- лимиты бюджета по категориям
- накопления ("копилки")
- аналитика по текущему месяцу и по тренду
- резервные копии и восстановление
- работа нескольких клиентов с общей серверной частью

## Варианты запуска

### Web-режим разработки

Самый простой способ для локальной разработки:

```bash
npm start
```

Что произойдёт:

- backend запустится на `:3002`
- frontend dev server запустится на `:5174`
- web-клиент будет обращаться к API через проксирование `/api`

### Production-запуск web-версии

```bash
npm run start:prod
```

В этом режиме:

- собирается production-версия клиента
- Express раздаёт `client/dist`
- API и web-приложение работают через сервер на `:3002`

### Запуск KMP-приложения

#### Android

```bash
cd mobile_app_client
./gradlew :composeApp:assembleDebug
```

#### Desktop

```bash
cd mobile_app_client
./gradlew :composeApp:run
```

#### iOS

Откройте `mobile_app_client/iosApp/iosApp.xcodeproj` в Xcode и соберите приложение.

## Первый вход в систему

После запуска приложения пользователь:

1. открывает экран входа
2. регистрирует новый аккаунт или входит в существующий
3. после логина попадает в защищённую часть приложения

В web-клиенте и KMP-клиенте используется авторизация по JWT.

## Основные экраны и сценарии

### Dashboard

Dashboard показывает сводную картину по текущему месяцу.

Основные элементы:

- карточки доходов и расходов с подписями плановых сумм (ожидаемые поступления / предстоящие списания)
- карточка «Прогноз на месяц»: свободный остаток и прогноз расходов с учётом ещё не наступивших регулярных платежей
- карточки накоплений и доступного остатка
- график динамики по последним 6 месяцам
- структура расходов по категориям
- быстрый обзор финансового состояния за месяц

### Month View

Это основной экран ежедневного учёта.

Что можно делать:

- переключать месяцы
- просматривать и редактировать доходы (сумма) и расходы (сумма + комментарий)
- добавлять новые записи
- задавать бюджетные лимиты по категориям
- разворачивать группы расходов по категориям
- менять порядок категорий через drag-and-drop
- управлять запланированными регулярными платежами (см. ниже)

Особенности:

- данные организованы вокруг месяца
- лимиты задаются отдельно для каждого месяца
- расходы группируются по категориям
- раскрытые списки показывают полный список записей категории

#### Запланированные платежи (план-слой)

Над списком расходов есть секция «Запланированные платежи» (и «Ожидаемые поступления» во вкладке доходов) — это регулярные платежи из фиксированных категорий/источников, которые ещё не наступили в этом месяце. По каждому плановому платежу доступно:

- **Оплачено / Получено** — подтвердить платёж сейчас (создаёт реальную запись досрочно; для платежей с флагом «требует подтверждения» это единственный способ их провести)
- **Пропустить в этом месяце** — исключить платёж только из текущего месяца, не трогая регулярную настройку
- **Изменить на этот месяц** — задать другую сумму или день списания только для этого месяца
- **Вернуть** — отменить пропуск

Наступившие регулярные платежи (без флага ручного подтверждения) создаются автоматически в свою дату.

### Categories

Экран категорий позволяет управлять справочниками приложения.

Доступно:

- создание категорий расходов
- переименование категорий
- изменение порядка категорий
- скрытие категорий через soft-delete
- управление источниками дохода
- настройка фиксированных (регулярных) платежей: сумма, день месяца и флаг «требует подтверждения оплаты/получения»

Важно:

- удаление категорий и источников дохода реализовано как деактивация, а не физическое удаление
- фиксированные платежи с флагом «требует подтверждения» не списываются автоматически — их нужно подтвердить кнопкой на экране «Месяц»

### Savings

Экран копилок используется для накоплений и целевых финансовых целей.

Возможности:

- создание копилок
- указание целевой суммы
- пополнение
- снятие средств
- отслеживание текущего прогресса

Важная бизнес-логика:

- пополнение копилки уменьшает доступный баланс месяца
- для этого на сервере создаётся скрытый расход в категории `"Пополнение копилки"`
- снятие средств оформляется как отрицательная транзакция копилки

### Settings

Экран настроек объединяет служебные функции и пользовательские настройки.

Обычно здесь доступны:

- профиль пользователя
- параметры интерфейса
- тема оформления
- безопасность
- резервные копии
- восстановление данных

## Резервные копии

Сервер поддерживает пользовательские резервные копии данных.

Особенности:

- бэкапы хранятся на сервере
- создаются JSON-снапшоты пользовательских данных
- действует ограничение на количество последних бэкапов
- восстановление выполняется транзакционно

## Синхронизация между клиентами

### Web-клиент

Web-клиент работает как online-клиент и получает данные через REST API и WebSocket.

### KMP-клиент

KMP-клиент работает по модели **offline-first**:

- сначала сохраняет изменения локально
- ставит операции в очередь синхронизации
- затем отправляет их на сервер
- при наличии сети подтягивает изменения с сервера

Это особенно важно для Android и desktop-режима, где пользователь может работать при нестабильном соединении.
