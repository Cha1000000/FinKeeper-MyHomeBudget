# План: ввод суммы как арифметического выражения (Excel-стиль) — веб + KMP

## Контекст

На экране «Месяц» (вкладки «Расходы»/«Доходы»), в диалоге «Добавить» пользователь вводит сумму.
Сейчас поле принимает только готовое число. Нужно дать вводить **арифметическое выражение**
по аналогии с полем «Формула» в Excel: например `=523+1275+104` → при сохранении/Enter
автоматически сворачивается в `1902`. Ведущий `=` опционален: `846+1036-14` тоже считается.

Изменения только на клиентах (веб + KMP). Сервер/БД/синк не трогаем — уходит готовое число.

## Семантика вычислителя (общая для обеих платформ)

Функция `evalAmount(input): number? / Double?`:
1. Нормализация: `trim`, убрать все пробелы, заменить `,` → `.`, срезать один ведущий `=`.
2. Пустая строка → null.
3. Разрешены только символы `0-9 . + - * / ( )`; иначе → null.
4. Разбор рекурсивным спуском с приоритетами: `expr := term (('+'|'-') term)*`,
   `term := factor (('*'|'/') factor)*`, `factor := '-' factor | '(' expr ')' | number`.
5. Деление на ноль / переполнение / не-финитный результат → null.
6. Результат округляется до 2 знаков (`round(x*100)/100`) — убираем float-артефакты (0.1+0.2).
7. Обычное число (`523`) проходит как есть — обратная совместимость.

Проверку «> 0» оставляем вызывающему коду (текущее правило сохраняется).

## Веб-клиент

**`client/src/utils.ts`** — добавить `export const evalAmount = (input: string): number | null`.

**`client/src/pages/MonthView.tsx`** (диалог добавления, `<form onSubmit={handleSubmit}>`):
- Поле суммы (строки ~1021-1028): `type="number"` → `type="text"`, добавить `inputMode="text"`,
  `autoComplete="off"`, оставить `required`, `placeholder="=523+1275+104"`.
- `handleSubmit` (строки ~410, 417): `parseFloat(formData.amount)` → `evalAmount(formData.amount)`;
  если `null` или `<= 0` → `setActionError('Некорректное выражение в поле суммы')` и `return`.
- **Live-превью** под полем: если ввод содержит оператор/`=` и `evalAmount` валиден — показать
  «= {результат} ₽» (формат через `Intl.NumberFormat('ru-RU', {maximumFractionDigits: 2})`);
  если невалиден — приглушённая красная подсказка. Если ввод — простое число, превью скрыто.

Enter уже сабмитит форму (нативно), отдельной обработки не нужно.

## KMP

**`composeApp/src/commonMain/.../util/AmountExpression.kt`** (новый) — `fun evalAmount(input: String): Double?`
(та же семантика). Тест **`commonTest/.../util/AmountExpressionTest.kt`**.

**`composeApp/src/commonMain/.../ui/screens/MonthViewScreen.kt`** — диалог добавления (`AddEntryDialog`,
строки ~789-920):
- Заменить `amount.toDoubleOrNull()` на `evalAmount(amount)` в `confirmButton.onClick` (~910)
  и в `enabled` (~918): `evalAmount(amount)?.let { it > 0 } == true`.
- Под полем суммы — **live-превью** «= 1 902 ₽» (когда ввод — выражение и валиден) либо
  приглушённая подсказка об ошибке.
- **Ряд операторов** под полем (мини-кнопки `=` `+` `−` `×` `÷` `(` `)` `⌫`): добавляют символ
  к строке `amount` (× → `*`, ÷ → `/`). Решает отсутствие операторов на Decimal-клавиатуре Android;
  на десктопе работает и физическая клавиатура.
- `imeAction = ImeAction.Done`, `onImeAction` — submit, если `evalAmount(amount)?.let { it > 0 } == true`.

Поле остаётся `KeyboardType.Decimal` (частый кейс — обычное число); операторы — через ряд кнопок.

## Консистентность (тот же вычислитель в остальных полях суммы)

Базовый deliverable — **диалог «Добавить»** (явный запрос). Поскольку замена тривиальна, тем же
`evalAmount` заменить парсинг в остальных полях суммы экрана «Месяц», чтобы поведение было единым:
- Веб: инлайн-правка суммы (`saveAmount`/`editingAmount`, инпуты ~876/973 → `type="text"`),
  подтверждение планового (`confirmAmount` ~634), override (`overrideForm.amount` ~612).
- KMP: `EditEntryDialog` (~1037), `ConfirmPlannedDialog`, `OverridePlannedDialog` (~1097),
  `AddPlannedExpenseDialog` (~988).

Без live-превью/ряда операторов в этих второстепенных местах (только парсинг) — чтобы не раздувать UI;
превью и операторы — в основном диалоге «Добавить».
