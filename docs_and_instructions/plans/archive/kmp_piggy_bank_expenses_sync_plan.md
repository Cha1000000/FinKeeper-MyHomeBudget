# KMP: пополнения копилки не уменьшают «Остаток» на экране «Месяц»

Дата: 2026-09-22 · Платформа: KMP (Android / iOS / Desktop) · Сервер и веб не меняются

## Симптом

На экране «Месяц» в плашке «Лимит трат» поле «Остаток» не уменьшается на сумму
пополнений копилки за месяц. В вебе та же плашка считает правильно. В KMP на экране
«Обзор» плашка «Лимит на расходы» тоже правильная. Володя подтвердил на телефоне:
разница ровно равна сумме пополнений.

## Первопричина

Формула везде одна: `max(0, сумма лимитов − все расходы месяца)`. «Все расходы»
включают скрытые расходы категории «Пополнение копилки». Сервер создаёт их при
пополнении копилки, а у самой категории `is_active = 0`.

| Где | Откуда «все расходы» | Результат |
|---|---|---|
| Веб, «Месяц» и «Обзор» | серверный список расходов месяца | верно |
| KMP, «Обзор» | `summary.expenses` с сервера (`DashboardViewModel.kt:218`) | верно (офлайн — неверно, см. ниже) |
| KMP, «Месяц» | сумма по **локальной БД** (`MonthViewModel.kt:295`) | **неверно** |

Почему в локальной БД нет скрытых расходов:

1. `ApiClient.getCategories()` (`ApiClient.kt:360`) запрашивает `/categories` без
   `include_inactive`, поэтому сервер отдаёт только активные категории.
   «Пополнение копилки» на телефон не попадает.
2. `ExpenseRepository.syncWithServerInternal` (`ExpenseRepository.kt:271-282`)
   пропускает расход, если его категории нет локально, а если он уже был,
   удаляет его. Так теряются все пополнения копилки.

Попутно так же теряются расходы из категорий, удалённых мягко
(`is_active = 0`): веб их учитывает, KMP — нет. Фикс лечит и это.

## Решение

Подтягивать с сервера **все** категории, включая неактивные. Тогда расходы-пополнения
и расходы удалённых категорий сохраняются в локальной БД как на сервере. Логика
расчёта остатка не меняется.

### Изменения в коде

1. **`data/remote/ApiClient.kt`** — `getCategories()` запрашивает
   `$baseUrl/categories?include_inactive=1`. Метод вызывается в одном месте
   (синхронизация категорий), другим вызовам это не навредит.
   Боевой сервер параметр уже поддерживает (`server/routes/data.js:61`,
   в прод-клоне AdminVPS тоже есть) — деплой сервера не нужен.

2. **`data/repository/category/CategoryRepository.kt`** — код не меняется:
   синхронизация уже переносит `isActive` с сервера во все три ветки
   (update / по имени / insert). Проверить это тестом, а не на глаз.

3. **`data/repository/expense/ExpenseRepository.kt`** — логику не меняю. Ветка
   «категории нет — выбросить расход» остаётся страховкой на случай настоящего
   рассинхрона. Обновлю устаревший комментарий про копилку.

### Почему неактивные категории не вылезут в интерфейс (проверено по коду)

| Место | Фильтр |
|---|---|
| Экран «Категории» | `CategoriesViewModel.kt:110-111`, `CategoriesScreen.kt:77,83,266` — `isActive == 1` |
| Диалог добавления/редактирования расхода в «Месяце» | `MonthViewScreen.kt:476` — `isActive == 1` |
| Диалог лимитов | `MonthViewScreen.kt:546` — `isActive == 1` |
| Список расходов «Месяца» | `MonthViewModel.kt:267-273` — расходы копилки отсекаются по имени категории |
| Разбивка «Обзора» | `DashboardViewModel.kt:238-243` — то же |
| План-слой (фиксированные категории) | SQL `getFixedCategoriesByUser`: `is_fixed = 1 AND is_active = 1` |

Расходы из удалённых категорий начнут отображаться в «Месяце» и в разбивке «Обзора»
под своим названием — так же, как в вебе.

### Что будет у существующих пользователей

Миграции БД не нужно. При следующей онлайн-загрузке экрана синхронизация категорий
добавит «Пополнение копилки» с `isActive = 0`, а синхронизация расходов месяца
вставит недостающие скрытые расходы. Каждый месяц «вылечится» при первом открытии
онлайн.

## Проверка

По правилу проекта — только на локальном сервере с временной БД, не на боевом.

1. **Автотест (desktopTest, настоящая SQLite в памяти)** — по образцу
   `SyncQueueIntegrationTest`: неактивная категория, пришедшая с сервера,
   сохраняется локально с `isActive = 0`, а расход по ней не выбрасывается.
   `ApiClient` сейчас создаёт HTTP-клиент сам, и подменить сервер в тесте нельзя.
   Если для теста придётся менять его конструктор (передавать `HttpClientEngine`),
   сначала обсужу это отдельно. Иначе проверка — сценарием ниже.
2. **Сценарий руками:** локальный сервер (`DB_PATH=./.ui-test.sqlite`, порт 3002) +
   `DEFAULT_SERVER_URL=http://localhost:3002 ./gradlew :composeApp:run`:
   - завести лимит, расход и пополнение копилки на 1 000 ₽;
   - «Остаток» в «Месяце» = «Лимит на расходы» в «Обзоре» = веб;
   - «Пополнение копилки» не видна в «Категориях», в выборе категории и в диалоге лимитов;
   - удалить категорию с расходом — расход остаётся в сумме, как в вебе.
3. `./gradlew composeApp:testDebugUnitTest` и desktop-тесты — зелёные.
4. Финальная проверка Володей на телефоне (релизная сборка, как с плашкой лимитов).

## Вне рамок (не делаю без отдельного решения)

- **Пополнение копилки офлайн.** KMP не создаёт скрытый расход локально: его создаёт
  сервер, и он приедет при синхронизации. До выхода в сеть остаток не уменьшится.
  Если создавать его локально, при синхронизации будет риск дубля.
- Офлайн-фолбэк в «Обзоре» (`DashboardViewModel.kt:218`, `:227`) после фикса
  сам станет правильным — отдельных правок не нужно.
